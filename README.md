ระบบครอบคลุม 4 งานที่ใช้งบประมาณก้อนเดียวกัน และทยอยพัฒนาเป็นเฟส

| งาน | ขอบเขต | เฟส |
| --- | --- | --- |
| 01 งานแผนงาน | ตั้งแผนปฏิบัติการ · จัดสรรงบตามโครงการ · อนุมัติคำขอซื้อ | เฟส 3 |
| 02 งานพัสดุ | จัดซื้อจัดจ้าง · ทะเบียนครุภัณฑ์ · ตรวจสอบประจำปี · จำหน่ายพัสดุ | **เฟส 1 — กำลังพัฒนา** |
| 03 งานการเงิน | เบิกจ่าย · ใบสำคัญ · ยืมเงินราชการ · คุมเงินคงเหลือรายหมวด | เฟส 2 |
| 04 งานบัญชี | ลงบัญชีสินทรัพย์ · ค่าเสื่อมราคา · งบการเงิน · รายงานต้นสังกัด | เฟส 4 |

## เฟส 1 — แบบสำรวจครุภัณฑ์โดยครู

Next.js (App Router) + Supabase — ฐานข้อมูลเดียว ใช้ร่วมกันทั้ง 2 หน้าจอกรอกข้อมูล

| หน้า | ใช้เมื่อ | รายละเอียด |
| --- | --- | --- |
| `/survey` | มือถือ เดินสำรวจในห้อง | ทีละขั้น 4 ขั้น **ถ่ายรูปนำ** → ที่ตั้ง → ตัวครุภัณฑ์ → สภาพ · จำห้องล่าสุด · บันทึกแล้วเพิ่มชิ้นถัดไปในห้องเดิมได้ทันที |
| `/entry` | คอมพิวเตอร์ กรอก 10–50 รายการรวด | ล็อกห้องไว้ที่หัวจอ · `Enter` = แถวใหม่ · `Ctrl/⌘ + D` = ทำซ้ำแถวบน (ล้างเลขครุภัณฑ์กับรูป) · ลากรูปหลายไฟล์มาวางแล้วจับคู่ตามลำดับแถว |
| `/items` | ตรวจทานก่อนส่ง | รายการของฉันแยกตามห้อง · แก้ไข/ลบเฉพาะที่ยังไม่ส่ง · กดส่งให้งานพัสดุ |

- เอกสารออกแบบต้นทาง: [design/phase1-asset-survey](design/phase1-asset-survey/)
- ฟิลด์บังคับ 5 อย่าง: ห้อง · ชื่อครุภัณฑ์ · จำนวน · สภาพ · รูป
  (ปี/แหล่งงบ/ราคา พับเก็บใต้ "ข้อมูลเพิ่มเติม")
- ระบบกันหมายเลขครุภัณฑ์ซ้ำภายในรอบเดียวกัน (เตือนตอนกรอก + unique index กันอีกชั้น)
- รายการที่ไม่มีรูปยังบันทึกเป็นฉบับร่างได้ แต่ **ส่งให้พัสดุไม่ได้จนกว่าจะมีรูปครบ**

### การเข้าใช้งาน

ครูไม่ต้องล็อกอิน — เปิดลิงก์แล้วกด **"เข้าใช้งานทั่วไป"** ปุ่มเดียวก็กรอกได้เลย
ไม่ต้องสมัคร ไม่ต้องใส่ชื่อ ไม่ต้องใส่รหัส
(เบื้องหลังใช้ anonymous sign-in ของ Supabase จึงยังมี `auth.uid()` ต่อคน
RLS และโฟลเดอร์รูปยังแยกกันตามเดิม)

- รายการที่กรอกผูกกับเบราว์เซอร์นั้นจนกดส่งให้งานพัสดุ — ถ้าล้างข้อมูลเบราว์เซอร์จะกลับมาดูไม่ได้
  (หน้าแรกเตือนไว้เมื่อยังมีรายการที่ยังไม่ส่ง)
- เจ้าหน้าที่พัสดุ/ผู้ดูแลระบบใช้อีเมล+รหัสผ่านตามปกติ เพื่อดูรายการของทุกคน
- ต้องเปิด **Anonymous sign-ins** ในแดชบอร์ด Supabase
  (Authentication → Sign In / Providers) — เปิดไว้แล้วในโปรเจกต์นี้

### สิทธิ์ผู้ใช้

| บทบาท | สิทธิ์ |
| --- | --- |
| `teacher` (ค่าเริ่มต้น — รวมผู้ใช้ทั่วไป) | เห็นและแก้เฉพาะรายการของตัวเอง และเฉพาะที่ยังไม่ส่ง |
| `supply` (เจ้าหน้าที่พัสดุ) | เห็น/แก้ได้ทุกรายการ · แก้ไขข้อมูลตั้งต้น (อาคาร หมวดหมู่ แหล่งงบ หน่วย) · เปิด–ปิดรอบสำรวจ |
| `admin` | สิทธิ์ทั้งหมด รวมถึงเปลี่ยนบทบาทผู้ใช้ |

บังคับด้วย Row Level Security ที่ฐานข้อมูล ไม่ใช่ที่หน้าจอ

## ติดตั้งเพื่อพัฒนา

```bash
npm install
cp .env.local.example .env.local   # ใส่ค่า NEXT_PUBLIC_SUPABASE_URL / ANON_KEY
npm run dev
```

### ฐานข้อมูล

รัน migration ใน [`supabase/migrations`](supabase/migrations/) ผ่าน Supabase CLI

```bash
supabase link --project-ref <project-ref>
supabase db push
```

หรือคัดลอกเนื้อไฟล์ไปรันใน SQL Editor ของ Supabase ก็ได้ (เขียนให้รันซ้ำได้ไม่พัง)

Migration จะสร้างให้ครบ: ตาราง `asset_*`, enum, RLS policy, bucket `asset-photos`,
trigger สร้างโปรไฟล์ให้ผู้ใช้ใหม่ และข้อมูลตั้งต้น (อาคาร/หมวดหมู่/แหล่งงบ/หน่วย + รอบปีการศึกษา 2569)

> ตารางทั้งหมดใช้ prefix `asset_` เพื่อให้ติดตั้งร่วมกับโปรเจกต์ Supabase เดิมได้โดยไม่ชนชื่อ

หลังรัน migration ให้ตั้งเจ้าหน้าที่พัสดุคนแรกด้วย

```sql
update public.asset_survey_profiles set role = 'admin' where user_id = '<uuid ของผู้ใช้>';
```

### สภาพแวดล้อมที่ใช้อยู่

| อย่าง | ค่า |
| --- | --- |
| โปรเจกต์ Supabase | `financial-asset-survey` (ap-southeast-1) — แยกจากโปรเจกต์อื่น |
| Migration | รันแล้วทั้งหมด (ตาราง · RLS · bucket · ข้อมูลตั้งต้น) |

### เรื่องที่ต้องตั้งค่าก่อนให้ครูใช้จริง

1. **บัญชีอีเมล (เฉพาะเจ้าหน้าที่)** — Supabase บังคับยืนยันอีเมล และ SMTP ในตัวจำกัด
   การส่งไว้ไม่กี่ฉบับต่อชั่วโมง ถ้าจะสร้างบัญชีเจ้าหน้าที่หลายคนควรตั้ง SMTP ของโรงเรียน
   ที่ Authentication → Emails ก่อน (ครูทั่วไปไม่ต้องใช้อีเมลอยู่แล้ว)
2. **ใครก็เปิดลิงก์แล้วกรอกได้** — โหมดใช้งานทั่วไปไม่มีรหัสกั้น ถ้าลิงก์หลุดออกไปนอกโรงเรียน
   คนนอกก็เพิ่มรายการเข้ามาได้ (แก้/ลบของคนอื่นไม่ได้) ถ้าต้องการกั้นภายหลัง
   ทำได้โดยเพิ่มรหัสร่วมของโรงเรียนหน้าปุ่ม หรือปิด Anonymous sign-ins แล้วออกบัญชีให้ครู
3. **ผังอาคาร–ห้องจริง** — แก้ตาราง `asset_buildings` ให้ตรงกับโรงเรียน
   (ตอนนี้ใส่ตัวอย่างไว้: อาคาร 1–4 · โรงฝึกงาน · โรงอาหาร · หอประชุม)
4. **รูปแบบหมายเลขครุภัณฑ์** — ตอนนี้เป็นข้อความอิสระ ไม่บังคับรูปแบบ
   (แค่กันเลขซ้ำ) ถ้าโรงเรียนมีรูปแบบตายตัวควรเพิ่ม validation

## โครงสร้างโค้ด

```
src/
  app/            หน้าเว็บ (App Router) — page.tsx, login, survey, entry, items
  components/     ส่วนประกอบร่วม — ฟอร์ม, ชิป, ปุ่มจำนวน, ช่องถ่ายรูป, toast
  lib/
    supabase/     client (เบราว์เซอร์) และ server (server component)
    data.ts       ชั้นเดียวที่คุยกับฐานข้อมูล — ใช้ร่วมกันทั้ง /survey และ /entry
    hooks.ts      โหลด master data · โปรไฟล์ · จำห้องล่าสุด (localStorage)
    types.ts      ชนิดข้อมูลตรงกับ schema
  proxy.ts        กันหน้าที่ต้องล็อกอิน + ต่ออายุ session (Next 16 เรียก middleware ว่า proxy)
supabase/migrations/
```

## สิ่งที่ยังไม่ได้ทำ (เฟส 1 ส่วนที่เหลือ)

- หน้าจอฝั่งเจ้าหน้าที่พัสดุ: ตรวจสอบ/อนุมัติ/ตีกลับ ออกเลขครุภัณฑ์ให้รายการ "ยังไม่ติดป้าย"
- ส่งออกบัญชีครุภัณฑ์ประจำปีเป็น Excel/PDF
- แดชบอร์ดหัวหน้ากลุ่มสาระ (ความคืบหน้ารายห้อง) และผู้บริหาร (มูลค่าสินทรัพย์รวม)
- QR บนป้ายครุภัณฑ์เพื่อเลิกพิมพ์เลขเอง
- กรอกแบบออฟไลน์ (คิวรออัปโหลดเมื่อสัญญาณกลับมา)
